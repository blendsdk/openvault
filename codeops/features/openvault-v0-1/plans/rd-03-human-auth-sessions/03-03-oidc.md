# OIDC Authentication: RD-03

> **Document**: 03-03-oidc.md
> **Parent**: [Index](00-index.md)

## Overview

This component owns the OIDC authorization-code flow with PKCE, state, and nonce; UserInfo
retrieval; identity linking and JIT provisioning; and the `GET /v1/meta/auth` capability endpoint.
It uses the approved `openid-client@6.8.8` library directly with a 5-second timed fetch. It never
uses the WebAFX OIDC controller or stores an access, refresh, or ID token.

## Architecture

### Current Architecture

The config loader already validates the OIDC issuer, client id, client secret, redirect URL, and
allowed domains. The database has `oidc_identities(issuer, subject)` and `principals`. The
`blendsdk/webafx-auth` OIDC provider cannot load without `openid-client`, and its controller stores
tokens, so it is not used.

### Proposed Changes

1. `oidc/client.ts` wraps discovery, the authorization URL, the code exchange, and UserInfo.
2. `oidc/state.ts` stores transient PKCE state in the memory cache and consumes it atomically.
3. `oidc/return-to.ts` validates the post-login redirect.
4. `oidc/identity.ts` links or provisions the principal.
5. `OidcController` implements `GET /v1/auth/login` and `GET /v1/auth/callback`.
6. `MetaController` implements `GET /v1/meta/auth`.

## Implementation Details

### OIDC Client

```ts
export interface OidcClientOptions {
  readonly config: OidcConfig;
  readonly fetch?: typeof globalThis.fetch;
  readonly now?: () => number;
}

export class OidcClient {
  constructor(options: OidcClientOptions);

  buildAuthorizationUrl(input: {
    readonly returnTo?: string;
  }): Promise<{
    readonly url: string;
    readonly state: string;
    readonly nonce: string;
    readonly codeVerifier: string;
  }>;

  exchangeCode(input: {
    readonly callbackUrl: URL;
    readonly codeVerifier: string;
    readonly nonce: string;
  }): Promise<{
    readonly subject: string;
    readonly claims: Record<string, unknown>;
    readonly userInfo: Record<string, unknown>;
  }>;

  health(): Promise<boolean>;
  shutdown(): Promise<void>;
}
```

Implementation notes:

- Discovery uses `openid-client` `discovery(new URL(config.issuer.href), config.clientId,
  config.clientSecret, undefined, { [client.customFetch]: timedFetch })`. The timed fetch wraps
  the supplied `fetch` (default `globalThis.fetch`) and adds `AbortSignal.timeout(5000)`.
- After discovery, call `client.enableNonRepudiationChecks(configuration)` so the ID-token
  signature is verified. Verify `configuration.serverMetadata().issuer` equals the configured
  issuer exactly.
- Cache the discovery configuration for one hour. The cache is a `Map` keyed by issuer.
- `buildAuthorizationUrl` generates the verifier, state, and nonce with the library helpers,
  calculates the S256 challenge, and calls `client.buildAuthorizationUrl(configuration, {
  redirect_uri, scope: "openid profile email", code_challenge, code_challenge_method: "S256",
  state, nonce })`. It returns the URL and the three transient values.
- `exchangeCode` calls `client.authorizationCodeGrant(configuration, callbackUrl, {
  pkceCodeVerifier, expectedNonce: nonce, expectedState: client.skipStateCheck,
  idTokenExpected: true })`. State is validated by the controller before this call. The response
  must contain an ID token; `response.claims()` must return an object with a string `sub`.
- `exchangeCode` calls `client.fetchUserInfo(configuration, response.access_token, subject)`.
  The library validates the UserInfo response shape and the `sub` equality.
- The method returns only `{ subject, claims, userInfo }`. It never returns or stores
  `access_token`, `refresh_token`, or `id_token`. Local variables go out of scope after the call.
- `health()` attempts discovery and returns a boolean; it is not used by readiness (an IdP outage
  must not fail readiness).
- `shutdown()` clears the discovery cache.

### State Store

```ts
export interface OidcState {
  readonly codeVerifier: string;
  readonly nonce: string;
  readonly returnTo: string;
  /** SHA-256 of the `__Host-ov_oidc` browser-binding cookie. */
  readonly bindingHash: string;
}

export class OidcStateStore {
  constructor(options: { readonly cache: CacheProvider; readonly now?: () => number });
  put(state: string, value: OidcState): Promise<void>;
  take(state: string): Promise<OidcState | undefined>;
  delete(state: string): Promise<void>;
  destroy(): Promise<void>;
}
```

- Key: `oidc:state:<sha256(state) hex>`.
- TTL: 600 seconds.
- `take` uses an in-flight `Set` keyed by the state hash: if the key is already in flight, return
  `undefined`; otherwise add it, read the cache, delete the key, and remove the in-flight marker in
  a `finally`. This makes a concurrent replay fail even though the cache has no atomic take.
- Login creates a 32-byte binding, stores only `sha256(binding)` in the state, and sets
  `__Host-ov_oidc` (HttpOnly, Secure, SameSite=Lax, Path=/, no Domain, 600 seconds). The callback
  requires the cookie, compares its hash in constant time, and clears it. This binds the flow to
  the browser that started it and prevents attacker-initiated login CSRF.
- `returnTo` is sanitized before storage and re-checked before the redirect. The sanitizer rejects
  any raw `//`, a resolved pathname starting with `//`, backslashes, control characters, and
  values over 2048 characters.

### returnTo Sanitization

```ts
export function sanitizeReturnTo(raw: unknown, baseUrl: URL): string;
```

- Return `"/"` for a non-string, empty, longer than 2048, or unsafe value.
- Reject a value that does not start with `/`, starts with `//`, contains `\`, a control character,
  CR, or LF.
- Resolve with `new URL(value, baseUrl)`; the result's origin must equal `baseUrl.origin`.
- Return the resolved pathname plus search, not the absolute URL.

### Identity Linking and JIT

```ts
export class OidcIdentityService {
  constructor(options: { readonly database: PostgreSQLDatabase; readonly now?: () => number });
  resolve(input: {
    readonly issuer: string;
    readonly subject: string;
    readonly claims: Record<string, unknown>;
    readonly userInfo: Record<string, unknown>;
    readonly allowedDomains: readonly string[];
  }): Promise<{ readonly principalId: string; readonly name: string; readonly email: string | null }>;
}
```

- Look up `oidc_identities` by `(issuer, subject)`. If found, join `principals`; reject a disabled
  principal with a generic `403 access_denied`.
- If not found, require JIT to be enabled (`allowedDomains.length > 0`). Otherwise reject with
  `403 access_denied`.
- Merge claims with UserInfo; UserInfo wins for `email`, `email_verified`, and `name`.
- Require `email_verified === true` and a non-empty `email` string. Normalize the email to
  lowercase and trim; reject over 320 characters.
- Require the email domain (the part after the last `@`) to exactly match one of the allowed
  domains. This is a case-insensitive exact match, not a suffix match.
- Check `principals` for an existing user with `lower(email) = :email`, including disabled rows.
  If one exists, reject with `403 access_denied` and log a sanitized `oidc_link_collision` event.
  Never auto-link by email.
- Derive `name` from the `name` claim when it is a non-empty string; otherwise use the email local
  part. Truncate to 100 characters.
- In one transaction, insert `principals(id, kind='user', name, email, status='active')` with a
  new ULID and insert `oidc_identities(principal_id, issuer, subject)`. If a unique violation
  occurs, re-query the identity; if it now exists, use it; otherwise rethrow. This handles a
  concurrent first login.
- JIT principals receive no role assignments. RBAC remains default-deny until RD-06.
- The identity lookup/insert is the only database write on the OIDC path. Tokens and claims are
  never persisted.

### OIDC Controller

```text
GET /v1/auth/login?returnTo=/projects
GET /v1/auth/callback?code=...&state=...
```

`GET /v1/auth/login`:

1. If `config.oidc` is undefined, return `404 oidc_not_configured`.
2. Apply the per-IP limiter (10/min).
3. Sanitize `returnTo`; default `/`.
4. Create a browser binding, `client.buildAuthorizationUrl`, store
   `{ codeVerifier, nonce, returnTo, bindingHash }` under the state, and set the
   `__Host-ov_oidc` cookie.
5. Redirect `302` to the authorization URL. A discovery outage maps to `503 oidc_unavailable`.

`GET /v1/auth/callback`:

1. If `config.oidc` is undefined, return `404 oidc_not_configured`.
2. Apply the per-IP limiter (10/min).
3. If the query contains `error`, consume the state if present, log only the error code, and
   return `400 oidc_callback_failed`.
4. Require a non-empty `state` and `code`. Consume the state with `take`. A missing or replayed
   state returns `400 oidc_callback_failed`. Require the `__Host-ov_oidc` cookie and compare its
   hash with `state.bindingHash`; a missing or mismatched binding returns `400` and clears the
   cookie.
5. Build the callback URL from `config.oidc.redirectUrl` plus the original query, and call
   `client.exchangeCode`. A flow failure (bad code, nonce, ID token, UserInfo subject) returns
   `400 oidc_callback_failed`; a timeout/network/5xx failure returns `503 oidc_unavailable`.
6. Resolve the identity with `OidcIdentityService`.
7. Create a session with `authMethod: "oidc"`, set the cookie, and redirect `302` to the sanitized
   `returnTo` (default `/`). The redirect response contains no token.
8. On a disabled principal or a JIT collision, return `403 access_denied` with a generic message.
9. The state is consumed on every path, including failures.

`GET /v1/meta/auth` (in `MetaController`, public):

```json
{ "local": true, "oidc": true }
```

`oidc` is `config.oidc !== undefined`. No secret or issuer detail is returned.

## Code Examples

### Callback exchange without token persistence

```ts
const state = await stateStore.take(stateParam);
if (state === undefined) {
  throw new ApiError(400, "oidc_callback_failed", "Sign-in failed");
}
const result = await oidc.exchangeCode({
  callbackUrl,
  codeVerifier: state.codeVerifier,
  nonce: state.nonce,
});
const principal = await identities.resolve({
  issuer: config.oidc.issuer.href,
  subject: result.subject,
  claims: result.claims,
  userInfo: result.userInfo,
  allowedDomains: config.oidc.allowedDomains,
});
const { secretId, record } = await sessions.create({
  principalId: principal.principalId,
  authMethod: "oidc",
});
setSessionCookie(res, secretId, remainingSeconds(record));
res.redirect(302, state.returnTo);
```

## Error Handling

| Error Case | Handling Strategy | AR Ref |
|---|---|---|
| OIDC not configured | `404 oidc_not_configured` | AR-14 |
| Provider `error` query | Consume state; `400 oidc_callback_failed`; log code only | AR-10 |
| Missing/replayed state | `400 oidc_callback_failed` | AR-10 |
| Missing/mismatched browser binding | `400 oidc_callback_failed`; clear the binding cookie | AR-10 |
| Bad code, nonce, ID token, or `sub` | `400 oidc_callback_failed` | AR-10 |
| Discovery/token/UserInfo timeout or 5xx | `503 oidc_unavailable` | AR-10 |
| Disabled principal | `403 access_denied` | AR-11 |
| JIT disabled | `403 access_denied` | AR-11 |
| Unverified email or disallowed domain | `403 access_denied` | AR-11 |
| Email collision | `403 access_denied`; sanitized log | AR-11 |
| Discovery issuer mismatch | Treat as unavailable; `503` | AR-19 |
| Token storage | Never store; assert in tests | AR-2 |

## Testing Requirements

- Spec tests with a fake HTTPS IdP for a valid login, state/nonce failure, replay, UserInfo `sub`
  mismatch, JIT allowed/denied, email collision, disabled principal, and `meta/auth`.
- Integration tests that assert no access/refresh/ID token appears in the cache, database, or
  captured logs.
- Unit tests for `sanitizeReturnTo`, state `take` concurrency, discovery cache expiry, and the
  timed fetch abort.
- The fake IdP validates PKCE `S256`, the nonce, the client id/secret, and the redirect URL.

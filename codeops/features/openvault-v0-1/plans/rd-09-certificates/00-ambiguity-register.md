## Resolution Notes

**AR-1:** Certificate routes reuse the RD-08 data-plane project-name selector; there is no new admin selector.

**AR-2:** Import and generate are create-or-renew by name. A new name returns 201; an existing active name returns 200 with a new immutable version. A soft-deleted name returns 409. No separate renewal route. An optional `expectedVersionId` guards a delayed retry.

**AR-3/4:** The database stores the normalized leaf and intermediates in `chain_pem`. Metadata never contains PEM; the public read returns `certificatePem` and `chainPem` separately.

**AR-5:** Fingerprints are 64 lowercase hex characters over the DER; serials are lowercase hex; SANs are canonical typed strings.

**AR-6/7:** Strict PEM labels, canonical base64, size bounds, PKCS#8 only, RSA 2048/3072 or EC P-256, and SPKI equality.

**AR-8:** Chain signatures are verified with `signatureOnly: true`; CA/keyCertSign is required on used intermediates. A chain that does not reach a self-signed root warns. A provided certificate that claims the leaf's issuer but fails the signature rejects 422; a chain that is not the leaf's issuer is dropped with a missing-intermediate warning.

**AR-9:** Not-yet-valid rejects 422 unless allowed; expired imports with a warning. No clock skew.

**AR-10:** Fixed generation profile: SHA-256 self-signed, CA false, server+client auth, typed SANs, 1–825 days, `notBefore` backdated 30 seconds.

**AR-11:** A 1,000-version safety limit bounds repeated renewals.

**AR-12:** Names are reserved until purge; a per-name advisory lock serializes import/renew/recover/purge; a project share lock serializes project deletion.

**AR-13:** `SecretPurger` becomes `VaultPurger` with both delete methods and one pool. The guard checks the database, session user, current user, superuser membership, and ownership of all five object tables.

**AR-14/15:** The certificate lifecycle mirrors RD-08. A PATCH route changes tags and enables one-way protection without a new version.

**AR-16/17:** The scheduler is in-process, disabled in tests, and runs a scan at startup and each configured hour. Only the current version of an active certificate in an active project is considered. Thresholds are 30/14/7 with nearest-threshold selection.

**AR-18/19/20:** A new notification table provides the durable claim, a one-hour lease for stale pending rows, and a stable audit event id. The webhook is optional, HTTPS-only except loopback HTTP in non-production, HMAC-signable with a timestamp, and carries a stable event id. Failures delete the claim for a later retry; a crashed claim is reclaimed.

**AR-21:** Import/generate/renew use one joined `certificate.write` event with `mode`/`renewal` details; public reads use `certificate.read`; private reads decrypt before writing one allow and write an error on decryption failure; expiry adds `certificate.expiry_warning` with a stable audit event id.

**AR-22:** Private reads require `certificate.read_private` and a 30/min limiter; import/generate use a 10/min limiter.

**AR-23:** Expired current or private reads return 410; `?version=` explicitly returns the stored version.

**AR-24:** Search supports subject, SAN, and expiry window with a name/id cursor.

**AR-25:** The certificate private key uses the existing v2 envelope with `objectType: "certificate"` and a 131,072-byte limit.

**AR-26:** New expiry-hour and webhook settings; `OPENVAULT_CERT_MAX_BYTES` is clamped to 131,072.

**AR-27:** No certificate route is exposed on the agent listener.

**AR-28:** No `Idempotency-Key` for import/generate; retries can create a new version.

**AR-29:** Tests use the real X.509 library, Node crypto, PostgreSQL, and a local webhook server.

**AR-30:** The notification table and the `certificate_versions.not_after` index are the only schema changes and are generated from `schema.ts`.

**AR-31:** `?version=<ulid>` is the only version selector; no versions-list route.

**AR-32:** No standing specialist.

**AR-33:** The full repository verification gate is the definition of done.

**AR-34:** `daysToExpiry` is computed; `chainLength` counts the leaf plus intermediates.

**AR-35:** Project list items carry `certificateCount`; the single-project contract stays unchanged.

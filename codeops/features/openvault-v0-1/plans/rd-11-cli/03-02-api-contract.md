# API Contract and Generated Client: RD-11 CLI

> **Document**: 03-02-api-contract.md
> **Parent**: [Index](00-index.md)

## Overview

This component turns the real WebAFX controllers into one committed OpenAPI 3.1 document and
one typed TypeScript client. The controllers remain the runtime authority; a single metadata
table supplies operation ids, tags, request/response schemas, security, and envelope behavior.
`pnpm api:check` rebuilds both artifacts in memory and fails on any drift.

## Architecture

```text
apps/server/scripts/api-contract.ts
  ├── CONTRACT_CONTROLLERS: real controller classes + base paths
  ├── ROUTE_DOCS: keyed by "METHOD /full/path"
  ├── buildApiDocument(): OpenAPIGenerator over instrumented route copies
  ├── generate(): write openapi.json + generateClient output
  ├── check(): compare document text + checkClient
  └── main(argv): generate | check

artifacts:
  packages/api-contract/openapi.json       # committed OpenAPI 3.1 document
  apps/cli/src/generated/types.ts          # generated types
  apps/cli/src/generated/client.<group>.ts # one file per tag
  apps/cli/src/generated/client.ts         # barrel
  apps/cli/src/generated/index.ts          # barrel
```

The generated files carry the `// Generated by \`blendsdk api generate\` — do not edit by hand.`
marker. `generateClient` prunes marker-bearing files that are no longer expected; `checkClient`
is read-only and reports stale marker files as drift, so a removed route fails `api:check` until
the client is regenerated.

## Implementation Details

### Metadata shape

```ts
/** One documented operation. */
interface RouteDoc {
  readonly operationId: string;
  readonly tags: readonly string[];
  readonly summary: string;
  readonly secure: boolean;
  readonly envelope?: "data" | "body";
  /** Query schema for GET/DELETE, body schema for POST/PUT/PATCH. */
  readonly input?: z.ZodType;
  readonly responses: ReadonlyArray<{
    readonly statusCode: number;
    readonly description: string;
    readonly schema?: z.ZodType;
  }>;
}
```

`ROUTE_DOCS` is `Record<string, RouteDoc>` keyed by `METHOD /full/path` using Express
`:param` segments. A missing entry or an entry with no matching real route is a contract error
with exit 2.

The table is the contract source for **schemas**; the real controllers are the source for
**paths and methods**. `api:check` therefore detects table/artifact drift and route drift, not a
controller schema change that leaves the table untouched. The command end-to-end tests are the
schema oracle: each representative request is sent to the real server and parsed by the shared
Zod contracts. This limitation is stated in the preflight report rather than overclaimed.

### Instrumentation

`instrumentRoute(basePath, definition)` returns a new `RouteDefinition`:

- `method` and `path` unchanged; `handler: () => undefined`.
- `secure: doc.secure`.
- `validation: doc.input` (generation only; the runtime controller still parses its own body).
- `openapi: { operationId, tags, summary, envelope, responses }`.
- No middleware, authorize, or auth metadata are copied; they do not affect the document.

The real controller is instantiated with `({}, {})`; `routes()` only builds definitions. No
database, network, or filesystem access occurs.

### Build and generate

```ts
/** Builds the contract document from the real controllers. */
export async function buildApiDocument(): Promise<OpenAPIDocument>;

/** Generates the document and client into explicit paths. */
export async function generateContract(options: {
  readonly outputDir: string;
  readonly contractFile: string;
}): Promise<void>;

/** Checks both artifacts without writing. */
export async function checkContract(options: {
  readonly outputDir: string;
  readonly contractFile: string;
}): Promise<{ readonly driftedFiles: readonly string[]; readonly issues: readonly ContractIssue[] }>;
```

The generator configuration:

```ts
{
  title: "OpenVault CLI API",
  version: "0.1.0",
  description: "The CLI-facing OpenVault API. Internal agent and browser routes are excluded.",
  securitySchemes: {
    bearerAuth: { type: "http", scheme: "bearer", bearerFormat: "JWT" },
  },
  defaultSecurity: [{ bearerAuth: [] }],
}
```

Client options:

```ts
{
  outputDir,
  splitByGroup: true,
  clientName: "OpenVaultClient",
  runtimeImport: "blendsdk/api-client",
}
```

`generate` writes the Prettier-formatted document with a trailing newline, then writes the
client. `check` formats the rebuilt document and compares bytes, then calls `checkClient`; it
reports `DRIFT: <sorted files>` and returns 1 on any difference or error-level issue. It never
writes or deletes files.

### Scripts

`apps/server/package.json`:

```json
{
  "scripts": {
    "api:generate": "tsx scripts/api-contract.ts generate",
    "api:check": "tsx scripts/api-contract.ts check"
  }
}
```

Root `package.json`:

```json
{
  "scripts": {
    "api:generate": "pnpm --filter @openvault/server api:generate",
    "api:check": "pnpm --filter @openvault/server api:check",
    "verify": "pnpm build && pnpm typecheck && pnpm api:check && pnpm lint && pnpm test && pnpm check:artifacts && pnpm check:react && pnpm docs:build"
  }
}
```

The script resolves the repository root from its own URL; it never depends on the current
working directory. `pnpm api:check` runs after `pnpm build`, so `@openvault/core` and
`@openvault/api-contract` `dist` outputs exist.

`biome.json` ignores `apps/cli/src/generated/**` and `packages/api-contract/openapi.json`:
the generator formats with single quotes and the repository uses double quotes. Those artifacts
are gated by `api:check`, not by Biome.

### Generated client use

`apps/cli/src/client/authenticated.ts` calls `createOpenVaultClient` from
`../generated/index.js` with the `HttpsAdapter` and `BearerAuth`. Commands use the typed groups:

```ts
client.auth.getCliMe();
client.projects.listProjects();
client.secrets.getSecret({ project, name });
client.certificates.generateCertificate({ project, name, subject, sans });
client.audit.verifyAudit();
client.scaffold.createScaffold({ project, service, entries });
```

The generated method parameter object is flat: path, query, and body fields are merged. The
runtime resolves path placeholders, serializes query values, and sends the remaining fields as
JSON. `Idempotency-Key` is passed per call through the generated method's second `options`
argument.

## Error Handling

| Error Case | Handling Strategy | AR Ref |
|---|---|---|
| Route has no metadata | `Missing API documentation for METHOD /path`, exit 2 | AR-6 |
| Metadata has no route | `Documented route does not exist`, exit 2 | AR-6 |
| Duplicate operationId | `ClientGenerationError`, exit 2 | AR-6 |
| Missing 2xx schema | `checkClient` error, exit 1 | AR-6 |
| Document differs | `DRIFT: openapi.json`, exit 1 | AR-6 |
| Client differs or stale marker file | `DRIFT: client.<group>.ts`, exit 1 | AR-6 |
| Contract package not built | Clear `MODULE_NOT_FOUND` message naming `pnpm build`; exit 2 | AR-29 |
| Controller schema changed, table unchanged | Representative E2E command tests fail against the real contract | AR-6 |
| Generated artifacts linted by Biome | Ignored paths; `api:check` owns their correctness | AR-52 |

## Testing Requirements
- A pure contract test builds the document and asserts every route in `CONTRACT_CONTROLLERS`
  has exactly one metadata entry, every operationId is unique, every non-public operation is
  secure, and every operation has a 2xx schema.
- A generation test writes both artifacts to a temp directory, asserts a clean check, mutates
  one generated file, and asserts drift; it also adds a stale marker file and asserts it is
  reported.
- The committed artifacts are checked by `pnpm api:check` in `pnpm verify`.
- A route added to a contract controller without metadata fails the contract test.
- The representative command E2E tests send real requests and parse the shared contracts, so a
  controller schema change that leaves the table stale is caught at the command boundary.

## Positive controls checked

- Envelope AAD domains are consistent across core, KEK rotation, restore, CA, audit-key, and signing-key code (`ov:v2`, `ov:dek:v2`, `ov:ca:v1`, `ov:audit-key:v1`, `ov:jwt:v1`).
- Browser cookies use `__Host-`, `HttpOnly`, `Secure`, `SameSite=Lax`, and `Path=/`; an `Authorization` header suppresses cookie fallback.
- CSRF uses both an Origin/Fetch-Metadata check and a per-session token for browser mutations; CLI bearer routes do not read the browser cookie.
- CLI refresh tokens are stored only as SHA-256 hashes; reuse revokes the family; password change revokes CLI families in the same transaction.
- Audit rows have a hash chain, HMAC, and checkpoints; append-only triggers exist, and the runtime role's `DELETE` on audit tables is revoked.
- The keyring file requires an absolute real path, owner match, non-writable directory, `0600` file mode, and `O_NOFOLLOW`; seeds and keys are zeroed where the runtime permits.

## Residual accepted risks

- Browser sessions, OIDC state, and login/refresh rate-limit counters are process-local; a restart signs users out and multi-instance operation is unsupported (`limitations.md:8,16,22,23`).
- No HSM: the KEK and CA key are on the same host; an application compromise can read every mounted secret (`limitations.md:2,24`). SEC-03 should be explicitly accepted if the runtime migrator secret remains intentional.
- KEK rotation and restore require a maintenance window; a running server can write an old `kek_id` after the rotation count check, and restore commits before post-commit verification (`limitations.md:49,55`).
- Audit tail truncation after the latest checkpoint and legitimate prefix pruning are indistinguishable without an off-box checkpoint anchor (`limitations.md:5`).
- Bootstrap `must_change=false` is currently accepted in `limitations.md:50`; if retained, the conflicting authentication guide and hardening checklist must be corrected.
- Node cannot reliably zeroize strings or runtime copies (`limitations.md:1`); this remains a best-effort property.

## Verdict

No Critical finding was identified. One High finding (SEC-01) is release-blocking under the repository's review-gate policy until fixed or explicitly accepted with a compensating control.

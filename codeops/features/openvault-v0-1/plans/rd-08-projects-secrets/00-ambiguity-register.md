## Resolution Notes

**AR-1:** Admin routes use the ULID; data routes use the active name. A project rename changes
the data path and any agent manifest that uses the old name. This is documented in the secrets
guide.

**AR-2:** Project deletion hides resources and blocks API purge of its secrets. RD-13 owns the
operator restore/backup path.

**AR-3/27:** Visibility is enforced in the repository, not only in controllers. The actor
snapshot, assignment list/lookup, access-explain candidates, and object resolution all apply
the parent-project and object-existence predicates. Dangling object-scope assignments are inert
and hidden.

**AR-4/31:** The project contract is `{id,name,createdAt,updatedAt,deletedAt}`; displayName is
not exposed. Capabilities reuse the existing RBAC contract.

**AR-5:** A write response returns metadata plus the written `version` so idempotent replay can
return the exact version even after a later write.

**AR-6:** Both encodings reject empty/all-whitespace decoded bytes. Text output requires valid
UTF-8 with no C0 controls except tab, newline, and carriage return; otherwise base64.

**AR-7:** The v2 AAD includes object type and project id in both the value and DEK-wrap
domains. Every AAD field is validated as a ULID, and the envelope validator rejects unknown
fields, non-canonical base64, wrong lengths, and over-limit ciphertext. The release
precondition requires empty version tables because the change is one-way.

**AR-8:** `latest` falls back to the newest unexpired version; it returns 410 only when no
version is active. `currentVersion` in metadata remains the stored pointer.

**AR-9:** Expiry must be in the future at write time. A past/equal expiry is a 422.

**AR-10:** Tag filters use `tagKey` and optional `tagValue`; this avoids the `=` ambiguity. A

**AR-11/30:** Authorize first, then claim; the request hash is an HKDF-derived KEK subkey HMAC;

**AR-16:** Capabilities appear on metadata and value responses, not on version or consumer

**AR-17/26/32:** State changes take the chain lock first, then data locks, then exactly one
